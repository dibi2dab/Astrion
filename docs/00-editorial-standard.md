# 편집 표준

이 문서는 Astrion에 어떤 글을 쓰고, 어떤 글을 쓰지 않으며, 무엇을 "좋은 글"로 간주하는지를 정의합니다. 코드가 검사할 수 있는 규칙은 가능한 한 자동 검증으로 옮겼고, 사람이 판단해야 하는 부분은 검수 상태(`provenance.review_status`)로 관리합니다.

## 1. 독자와 언어

- **언어**: 미국 영어(`en-US`)만 사용합니다. 제목, 훅, 본문, 표, 캡션, 메타 설명, 라벨, 출처 설명에 한글을 넣을 수 없습니다. 스키마가 한글을 감지하면 모듈 로딩 자체를 거부합니다.
- **독자**: 과학·수학에 관심은 있지만 해당 분야의 전공자는 아닌 성인 독자입니다. 대학 교양 수준의 배경지식을 가정하고, 전문 용어는 처음 등장할 때 정의합니다.
- **문체**: 설명문. 1인칭 감상, 과장, 클릭베이트, "충격적인 사실" 같은 표현을 쓰지 않습니다. 결론을 먼저 제시하고 근거를 뒤에 붙입니다.
- **길이**: 콘텐츠 유형별 최소 단어 수를 지킵니다(기본 600, 대부분 700, 연구 분석 800). 품질 게이트는 단어 수 미달을 치명적 실패로 처리합니다.

## 2. 주제 영역

Astrion은 다음 9개 주제 영역만 다룹니다. 사회과학, 인문학, 정치, 종교, 의학적 조언은 범위 밖입니다.

| 주제 영역 (`main_category`) | 다루는 예 |
| --- | --- |
| Mathematics | 대수, 해석, 기하, 확률, 정수론, 위상 |
| Physics | 역학, 전자기학, 열역학, 양자역학, 상대성이론 |
| Chemistry | 원자·분자 구조, 반응, 열화학, 유기화학 |
| Biology & Life Sciences | 세포, 유전, 진화, 생태, 신경과학 |
| Space & Astronomy | 행성, 항성, 우주론, 관측 천문학 |
| Earth & Natural Sciences | 지질, 기상, 해양, 기후 시스템 |
| Computing & Formal Sciences | 알고리즘, 계산 이론, 논리, 정보 이론 |
| Engineering & Applied Sciences | 재료, 구조, 로봇, 에너지 시스템 |
| Emerging & Interdisciplinary Science | 복잡계, 합성생물학, 과학 계산 등 융합 주제 |

보조 라벨(`labels`)은 Blogger의 보조 레이블로 쓰이며 최대 4개입니다. 첫 번째 Blogger 레이블은 항상 `main_category`이고, 보조 라벨은 주제 영역 이름을 반복할 수 없습니다.

## 3. 콘텐츠 유형

| `content_type` | 목적 | 최소 단어 수 |
| --- | --- | --- |
| `latest-discovery` | 최근 발표된 연구 결과를 맥락과 함께 설명 | 700 |
| `scientific-breakthrough` | 분야를 바꿀 수 있는 성과를 검증 가능한 형태로 정리 | 700 |
| `unsolved-problem` | 아직 풀리지 않은 문제와 접근법 소개 | 700 |
| `mathematics-explained` | 수학 개념·정리·증명 아이디어 설명 | 700 |
| `science-explained` | 자연 현상의 원리 설명 | 700 |
| `research-analysis` | 논문·데이터·방법론을 비판적으로 분석 | 800 |
| `experiments-data-modeling` | 실험 설계, 측정, 데이터 모델링 | 700 |
| `emerging-science` | 초기 단계지만 중요한 융합·신생 분야 | 700 |
| `basic-knowledge` | 기초 개념의 정확한 정의와 오해 교정 | 600 |

`latest-discovery`, `scientific-breakthrough`, `research-analysis`는 **1차 출처**(동료 심사 논문, 정부·공공기관, 표준 문서)를 최소 1개 요구합니다. 이 요구는 검증 단계와 품질 게이트 양쪽에서 강제됩니다.

## 4. 발행 리듬

- 하루 **2개**만 발행합니다(`site.posts_per_day: 2`).
- 발행 슬롯은 `America/New_York` 기준 `08:30`, `15:30`입니다.
- 한 번의 발행 워크플로 실행에서 최대 **1개**만 실제로 발행합니다(`blogger.max_per_run: 1`). 나머지는 다음 실행에서 처리됩니다.
- 품질을 채우지 못하면 **숫자를 채우지 않습니다**. "오늘 2개를 못 채웠다"는 실패가 아니라 정상 상태입니다.

## 5. 주제 선정 원칙

1. **설명 가능한 질문이 있어야 합니다.** "왜 하늘은 파란가?"처럼 한 문장으로 질문을 쓸 수 없으면 주제가 아직 흐릿한 것입니다.
2. **하나의 중심 원리로 설명합니다.** 여러 원리를 나열하는 대신, 글 전체를 관통하는 핵심 원리를 `central_principle`에 명시합니다.
3. **독자가 얻는 것이 분명해야 합니다.** `unique_value`는 "이 글만의 각도"를 80자 이상으로 서술합니다. 단순 요약은 고유 가치가 아닙니다.
4. **오해를 다룹니다.** 최소 1개의 흔한 오해를 `misconceptions`에 넣는 것을 권장합니다. 없으면 품질 점수가 낮아집니다.
5. **검증 가능한 출처를 붙입니다.** 교과서, 동료 심사 논문, 기관 자료, 표준, 신뢰할 수 있는 참고 자료를 사용합니다. 블로그·위키백과 단독 인용은 피합니다.
6. **사회과학·의학 조언·정치 논평은 제외합니다.** 과학적 방법으로 검증 가능한 자연·형식·공학 주제에 집중합니다.

## 6. 중복의 정의

Astrion은 제목이 달라도 같은 글이라고 판단합니다. 중복 판정의 핵심은 **편집 서명(editorial signature)** 입니다.

```text
editorial signature = core_question + explanation_target + central_principle
```

다음 중 하나라도 걸리면 중복 후보입니다.

- 같은 `topic.id`
- 편집 서명의 토큰 유사도 ≥ 0.70
- 편집 서명의 문자열 유사도 ≥ 0.85
- 제목 유사도 ≥ 0.92
- 같은 `primary_keyword`
- 같은 `aliases` 항목
- 이미 발행된 주제와 위 신호가 겹침

두 주제가 의도적으로 비슷하지만 다른 각도를 다룬다면 `distinct_from`에 상대 `topic_id`와 40자 이상의 설명을 적습니다. 이 예외는 **명시한 상대에만** 적용되며, 다른 주제와의 충돌은 막지 못합니다.

## 7. 글의 구조

Astrion은 고정된 목차를 강제하지 않습니다. 다만 다음 요소를 권장하며, 렌더러는 이 요소들을 일관된 HTML로 출력합니다.

- **훅(`hook`)**: 첫 문단. 질문을 던지거나 직관적인 장면에서 시작합니다.
- **핵심 요약(`key_takeaways`)**: 3~5개. 글을 읽지 않아도 핵심을 알 수 있어야 합니다.
- **본문 섹션(`sections`)**: 3~10개. 각 섹션은 하나의 논점을 다룹니다.
- **오해(`misconceptions`)**: 주장과 교정을 한 쌍으로 씁니다.
- **출처(`sources`)**: 본문 주장의 근거. `further_reading`은 심화 자료입니다.
- **관련 글(`related`)**: 대상 주제가 이미 발행되어 URL이 있을 때만 링크가 렌더링됩니다.

### 문단과 문장

- 문단 평균 75단어 이하를 목표로 합니다. 95단어를 넘으면 품질 경고가 발생합니다.
- 평균 문장 길이 25단어 이하를 목표로 합니다. 30단어를 넘으면 감점됩니다.
- 한 섹션당 80~400단어가 읽기 좋습니다.
- 수식은 문장의 일부로 읽히도록 설명을 붙입니다.

## 8. 수학 표기

- 인라인 수식은 `\( ... \)`, 디스플레이 수식은 `\[ ... \]`를 사용합니다.
- `equation` 블록은 기호 정의(`variables`)를 반드시 포함합니다. 기호, 의미, 필요하면 단위를 적습니다.
- 중괄호, 괄호, `\(`/`\)`, `\[`/`\]`의 짝이 맞아야 합니다. 품질 게이트가 균형을 검사합니다.
- LaTeX는 MathJax 3로 렌더링됩니다. 외부 스크립트는 MathJax CDN만 허용됩니다.
- 수식이 없는 글은 표기 점수에서 만점을 받습니다. 수식이 있는 글은 기호 정의와 균형을 모두 만족해야 만점입니다.

## 9. 표·목록·콜아웃·예제

- **표**: 2~6열, 1~30행. 모든 행의 셀 수가 같아야 합니다. 캡션은 필수입니다. 모바일에서 가로 스크롤되도록 렌더링됩니다.
- **목록**: 항목 1~12개. 순서가 중요하면 `ordered: true`.
- **콜아웃**: `tone`은 `key`, `note`, `warning` 중 하나입니다. 남용하지 않습니다.
- **예제**: 제목, 1~12단계, 선택적 결론. 계산 과정이나 실험 절차에 사용합니다.

## 10. 제목·메타·키워드

| 필드 | 제약 | 지침 |
| --- | --- | --- |
| `title` | 20~80자 | 질문형 또는 명확한 설명형. 숫자·과장 금지 |
| `seo_title` | 20~80자, 선택 | 비우면 `title` 사용 |
| `slug` | 소문자 kebab-case, ≤ 80자 | 파일명과 일치해야 함 |
| `meta_description` | 80~160자 | 결론과 범위를 포함. Blogger에는 자동 전송되지 않음 |
| `primary_keyword` | 3~80자 | 제목에 포함되면 SEO 점수 획득 |
| `secondary_keywords` | 최대 8개 | 본문에 자연스럽게 등장해야 함 |

`meta_description`은 큐와 품질 검사에는 쓰이지만 **Blogger API v3가 게시물 메타 설명을 설정하는 필드를 제공하지 않습니다**. Blogger 테마나 편집기에서 별도로 설정해야 합니다.

## 11. 출처와 사실 기준

`provenance.fact_basis`는 다음 중 하나입니다.

- `textbook`: 교과서·표준 개론서 기반
- `peer_reviewed`: 동료 심사 문헌 기반
- `agency_data`: NASA, NOAA, NIST 등 기관 자료 기반
- `editorial_synthesis`: 여러 자료를 편집자가 종합

`editorial_synthesis`는 출처를 최소 2개 요구합니다. 그 외 기준도 출처가 많을수록 정확성 점수가 높습니다.

각 출처는 `id`, `title`, `publisher`, `url`, `kind`, `accessed_at`을 가집니다. URL은 공개 호스트의 절대 `http(s)` 주소여야 하며 `example.com`, `localhost`는 거부됩니다. `accessed_at`이 미래 날짜이면 경고가 발생합니다.

## 12. 검수 상태

`provenance.review_status`는 `draft` → `reviewed` → `approved` 순서로 올립니다.

- `draft`: 작성 중. 발행 불가.
- `reviewed`: 사실·표현 1차 검토 완료. 아직 발행 불가.
- `approved`: 발행 가능. 품질 게이트의 필수 조건.

`status: active`인 모듈이 `approved`가 아니면 검증 경고가 나고, 발행 계획에서 제외되며, 품질 게이트는 무조건 `BLOCK`합니다.

> **주의**: 현재 저장소의 샘플 2개는 파이프라인 검증용 시드 콘텐츠이며 `review_status: approved`로 표시되어 있습니다. 첫 라이브 발행 전에 인용과 수치를 사람이 다시 확인하십시오.

## 13. 금지 사항

- 한글 또는 비영어 본문
- `TODO`, `TBD`, `lorem ipsum`, `[insert ...]`, `placeholder` 같은 자리표시자
- 확인되지 않은 수치, 인용, "연구에 따르면"식 모호한 출처
- 다른 글의 제목만 바꾼 재게시
- 블로그·SNS 요약만을 근거로 한 사실 주장
- 클릭베이트, 공포 마케팅, 과도한 수식어
- 사회과학·정치·종교·의학적 진단·투자 조언
- 이미지에 `alt` 텍스트 없이 삽입
- 고정 픽셀 너비로 모바일 레이아웃을 깨뜨리는 인라인 스타일
- `<script>` 임의 삽입 (MathJax 설정만 허용)

## 14. 편집 체크리스트

발행 전에 다음을 확인합니다.

- [ ] 한 문장으로 된 핵심 질문이 있는가?
- [ ] `central_principle`이 글 전체를 관통하는가?
- [ ] `unique_value`가 "요약"이 아니라 "차별점"을 말하는가?
- [ ] 최소 1개의 신뢰할 수 있는 출처가 있는가?
- [ ] 1차 출처가 필요한 유형인가? 그렇다면 포함했는가?
- [ ] 흔한 오해를 최소 1개 다루었는가?
- [ ] 표의 행/열이 맞고 캡션이 있는가?
- [ ] 수식 기호가 모두 정의되었는가?
- [ ] 한글·자리표시자가 없는가?
- [ ] 기존 글과 편집 서명이 겹치지 않는가?
- [ ] `review_status`가 `approved`인가?
